# explain

읽는 사람은 PROFILE.md 에 있다. "강함" 영역은 설명을 생략하고 비유의 기준으로 쓴다.

## 입력과 출력
- 입력: 설명할 대상(파일, 코드 범위, README, 개념, 정할 일)과 질문 한 줄. 대상을 먼저 읽는다. 읽지 않은 것은 설명하지 않는다.
- 출력: 아래 두 모양 중 하나. 30줄 이하는 터미널, 넘으면 docs/reports/<HHMM>-<주제>.md.

- 이해시키는 질문(뭐야, 어떻게, 왜)이면 references/shape-a.md 의 순서로 쓴다.
- 정하게 하는 보고(조사, 실측, 설계, 리뷰, 제출 전)면 references/shape-b.md 의 순서로 쓴다.

## 문장
- 한 문장에 사실 하나. 모든 문장에 동사. "·" 나 "→" 로 이은 조각 줄은 쓰지 않는다.
- 새 낱말은 쓰기 전에 괄호로 푼다. 비유를 먼저, 공식 용어를 다음에 쓴다.
- 그가 읽지 않은 코드를 아는 것처럼 말하지 않는다. 코드 첫 줄에 출처(파일:줄)를 쓴다.
- ★ 는 세 개까지. 요약 위의 요약, 칭찬, 맺음말은 쓰지 않는다.
- 파일로 쓰면 터미널에는 경로와 결론 한 줄만 쓴다.
