# explain understand — 이해시키는 설명

## 절차
1. 질문을 한 문장으로 다시 쓴다. 대상(파일, 함수, 동작)을 정한다.
2. 대상을 읽는다. 동작이면 실제로 돌려서 값을 얻는다 (예: `curl -s localhost:8000/api/...`, `python3 -c ...`). 돌릴 수 없으면 "돌려 보지 않음" 이라고 쓴다.
3. 아래 일곱 칸을 이 순서로 쓴다.

## 일곱 칸
1. 답 한 문장: 질문에 대한 직접 답.
2. 뼈대 한 문장: 부품들을 하나로 묶는 핵심. "이 앱은 결국 X 를 Y 로 바꿔 Z 에 보여 주는 것이다" 꼴. 부품만 있고 뼈대가 없으면 틀린 설명이다.
3. 그림 하나: 코드 블록 안 상자 그림. 15줄 이하, 폭 70자 이하. 상자 안에 파일 이름을 쓴다.
4. 실제로 한 번 따라가기: 요청 하나나 자료 한 줄이 어느 파일의 몇 번째 줄을 지나 화면에 닿는지 실제 값으로 쓴다. 단계마다 한 줄, 값이 어떻게 바뀌는지 보인다.
5. 부품 표: 부품 / 하는 일 / C++·엔진으로 치면 (anchors.md) / 공식 용어 (출처).
6. 왜 이렇게 했나: 대안 하나와 비교하고 무엇을 버렸는지 쓴다. 근거가 plan.md 나 담당자 답(Q#)에 있으면 붙인다.
7. 더 팔 곳 두세 개: 한 줄씩. 고르는 것은 사용자다.

## 하지 않는 것
- 사용자가 묻지 않은 부분 전체를 설명하지 않는다.
- 문법 강의를 하지 않는다 (PROFILE.md: Python 은 읽을 수 있다).
