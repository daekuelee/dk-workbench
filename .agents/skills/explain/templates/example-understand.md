질문: "밀린 티켓 숫자는 어떻게 화면까지 오는 거야?"

1. **답:** 서버가 시작할 때 CSV 를 한 번 읽어 두고, 브라우저가 /api/overdue 를 부르면 그때 기준에 맞는 티켓을 세어 JSON 으로 돌려준다.

2. ★ **뼈대:** 이 앱은 결국 "티켓 목록을 밀림 기준 하나로 걸러 담당자별로 센 표" 를 화면에 보여 주는 것이다.

3. **그림**
```text
data/tickets.csv ──(시작 때 1회)──► app/data.py  load_tickets()
                                          │ 정리: 대소문자, 날짜 형식, 중복
                                          ▼
브라우저 index.html ──fetch──► app/main.py  /api/overdue
                                          │ is_overdue(t, today)   app/rules.py
                                          ▼
                       {"미배정": 3, "김": 2, ...}  ──► 표로 그림
```

4. **실제로 한 번 따라가기** (curl 로 돌려 본 값)
- `app/data.py:18` 에서 T-0042 줄을 읽는다. status 가 "OPEN" 이다.
- `app/data.py:25` 에서 소문자로 바꾼다. "open" 이 된다.
- `app/rules.py:9` 에서 생성 후 4일, 우선순위 "높음" 이므로 1일 기준을 넘는다. 밀림이다.
- `app/main.py:31` 에서 담당자가 빈칸이라 "미배정" 칸에 1을 더한다.
- 응답 `{"미배정": 3, ...}` 이 `static/index.html:40` 에서 표 첫 줄로 그려진다.

5. **부품 표**
| 부품 | 하는 일 | C++·엔진으로 치면 | 공식 용어 |
|---|---|---|---|
| load_tickets | CSV 를 읽고 정리 | 초기화 때 리소스 로딩 | 데이터 로딩 (Python csv 모듈) |
| /api/overdue | 요청을 받아 집계를 돌림 | 디스패치 테이블의 핸들러 | 라우트 핸들러 (FastAPI 문서) |
| is_overdue | 밀림 기준 한 곳 | 규칙 함수 하나에 정책을 모음 | 비즈니스 규칙 |

6. **왜 이렇게 했나:** 기준을 rules.py 한 곳에 모았다. 대안은 SQL 이나 화면 JS 에서 거르는 것이었다. 버린 이유는 기준이 바뀔 때(Q4, Q5) 고칠 곳이 한 곳이어야 해서다.
