# 보고서 쓰기

## 읽는 사람
- 이 저장소의 주인이다. C++ 엔진 개발자이고, 웹과 이 업무의 도메인은 처음이다.
- 그림과 표를 먼저 읽고, 문단은 근거가 필요할 때만 읽는다.
- 한 번에 결정 하나를 내린다. 선택지에는 "왜"와 비교가 붙어야 결정한다.
- 정의되지 않은 낱말이 나오면 거기서 읽기를 멈춘다.

## 순서 (바꾸지 않는다)
1. `결론:` 한 문장.
2. `정할 것:` 지금 그가 정할 것 하나와 너의 추천, 추천 이유 한 문장. 없으면 "없음".
3. 그림 하나: 코드 블록 안의 상자 그림. 15줄 이하, 폭 70자 이하.
4. 표 하나: 선택지나 항목 비교. 열 이름은 내용에 맞게 고정한다 (예: 선택지 / 왜 / 대안 / 위험).
5. 근거: 한 줄에 출처 하나. 파일:줄, 명령과 결과, 담당자 답(Q#) 원문.
6. 모르는 것: 확인 안 된 것과 확인 방법. 추정은 A# 로 적는다.

## 문장
- 한 문장에 사실 하나를 쓴다. 모든 문장에 동사가 있다.
- "·" 나 "→" 로 이은 조각 줄을 쓰지 않는다. 화살표는 그림 안에서만 쓴다.
- 업무 용어와 웹 용어는 처음 나올 때 괄호로 풀어 쓴다.
- 꼭 읽어야 하는 줄 앞에 ★ 를 붙인다. 한 보고서에 세 개까지.
- 코드를 보일 때는 첫 줄 주석에 출처를 쓴다: 이번에 만든 파일:줄, 또는 라이브러리 이름.
- 요약 위에 요약을 쓰지 않는다. 칭찬, 다짐, 맺음말을 쓰지 않는다.

## 길이와 자리
- 한 보고서는 60줄 이하다. 넘으면 주제를 나눠 파일 둘로 쓴다.
- 파일: docs/reports/<HHMM>-<주제>.md. 터미널에는 파일 경로와 결론 한 줄만 쓴다.

## 종류별 그림
| 종류 | 그림 |
|---|---|
| 도메인 조사 | 세 칸 지도: 아는 것 / 담당자 확인 필요 / 모름 |
| 데이터 실측 | 열 표 (열, 타입, 빈칸, 이상한 값, 개수) |
| 설계 | 상자와 화살표: 화면 → API → 데이터, 파일 이름 포함 |
| 리뷰 | R# 표가 그림을 대신한다 |
| 제출 전 | 동작하는 것 / 약한 곳 / 다음 검증 세 칸 |
