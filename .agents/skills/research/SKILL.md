# research — 판단을 막는 질문에 근거를 구한다

조사 질문과 이 답으로 정할 것을 먼저 밝힌다. 현재 이해가 없으면 주어진 맥락에서 짧게 제시하고 조사할 범위를 좁힌다. 답과 확인 못 한 점이 드러나면 끝낸다. 더 조사할 거리가 있다는 이유로 범위를 늘리지 않는다.

## op와 입력
- domain: 업무 질문, README, 지금까지의 파트너 답·자료. [ops/domain.md](ops/domain.md)를 읽는다.
- tech: 만들 기능과 기술 질문, plan의 제약·기존 설계. [ops/tech.md](ops/tech.md)를 읽는다.
- docs/context.md에 필요한 자료·환경 정보가 있으면 재사용한다. 이미 확인한 사실을 다시 조사하지 않는다.

## 근거와 기록
- 조사 전에 references/sources.md에 따라 로컬 자료·모델 지식·웹 중 필요한 출처를 고르고 이유를 짧게 밝힌다. 웹 검색·원문 수집은 해당 질문에 대한 사용자 허락을 받은 뒤 한다.
- [references/sources.md](references/sources.md)에 따라 확인한 사실·후보·미확인을 구분한다. 모델 지식은 출처를 밝히고 확인 전으로 표시한다.
- 사용자에게 보여 줄 결론과 근거·한계를 쓴다. 긴 설명이 필요하면 explain의 표현 기준을 참고한다. 고정된 개수의 용어·후보·표를 채우지 않는다.
- 메인 세션은 AGENTS.md의 “대화에서 남길 기록”을 따른다. 조사 중 생긴 확인 질문과 후속 답변도 기존 Q에 연결하고, 사용자가 채택한 선택은 plan에 반영한다. 상세 근거는 docs/reports에 두며 짧은 조사라면 관련 기록에 근거를 함께 남겨 별도 보고서를 생략한다. 조사만으로 요구·설계를 확정하지 않는다.
- 별도 역할에 웹 조사를 맡기면 메인이 사용자에게 허락받은 질문과 범위를 state의 현재 조사 기록에 남긴다.
- 읽기 전용 역할 세션에서는 답만 반환한다. 보고서 저장은 ask.sh가, 진행과 채택 기록은 메인이 맡는다. 역할은 파일 쓰기 승인을 요청하지 않는다.
- 이미 요청받은 범위의 조사는 끝까지 한다. 새로운 업무 기준이나 기술 선택을 채택할 때는 사용자의 판단을 받는다.

## 필요할 때 참고

- [references/rulings.md](references/rulings.md): 과거 판정의 근거. 현재 절차는 SKILL과 ops를 따른다.

- 설명 수준은 PROFILE.md를 따른다. 이미 아는 기초까지 조사하지 않는다.
