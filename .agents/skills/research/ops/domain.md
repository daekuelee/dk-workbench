# research domain — 이 일을 현업에서 어떻게 하나

## 절차
1. 조사 질문을 한 문장으로 쓴다. 이 답으로 사용자가 무엇을 정하게 되는지 한 문장을 붙인다.
2. README, docs/questions.md(지금까지의 파트너 답), docs/state.md 를 읽는다. 파트너가 이미 말한 것은 "아는 것" 이다.
3. 자료 파일이 있으면 직접 센다 (setup read 의 1번과 같은 방법). 이미 setup 에서 셌으면 그 결과를 쓴다.
4. 아래 다섯 칸을 쓴다.

## 다섯 칸
1. 현업에서 보통 어떻게 하나: 5줄 이하. 모델 지식이면 "(확인 전)".
2. 영역 지도 그림: 아는 것(파트너 답, 자료) / 파트너 확인 필요 / 모름, 세 칸.
3. 용어 다섯 개와 한 줄 뜻. 사용자가 파트너와 대화할 때 쓸 말이다.
4. 이 팀이 가졌을 방식 후보 셋. 후보마다:
   - 후보 한 줄 "(확인 전)"
   - 파트너에게 던질 확인 질문 하나: "보통 ○○라고 하던데, 팀장님도 그렇게 보세요?" 꼴. 사소하고 구체적으로. 해결 방법을 묻지 않는다.
   - 답에 따라 바뀌는 설계 한 줄
5. 자료에서 본 사실: 행 수, 열, 빈칸, 이상한 값, 중복, 개인정보. 없으면 생략.
