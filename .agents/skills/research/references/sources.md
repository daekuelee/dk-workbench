# 출처를 고르고 확인하는 기준

## 조사 전에 고른다
기본은 웹을 쓰지 않는다. 제공 자료·기존 기록·로컬 확인과 모델 지식으로 먼저 판단하고, 모델 지식의 미확인은 밝힌다. 이 질문에 필요한 출처와 이유를 짧게 설명한다. 매번 별도 표를 만들 필요는 없다.

| 필요한 답 | 사용할 근거 | 주의할 점 |
|---|---|---|
| 이 과제의 사실·이 팀의 방식 | README·제공 자료·파트너 답 | 일반 지식으로 팀 기준을 대신 정하지 않는다 |
| 개념 이해·업무 가설·선택지의 초기 윤곽 | 모델 지식과 이미 확보한 자료 | 모델 지식이라고 밝힌다. 이 팀 적용과 확인하지 않은 기술 사실은 미확인으로 둔다 |
| 최신 정보·버전별 동작·정확한 사용법·출처가 필요한 주장 | 관련 공식 원문 등 웹 자료 | 웹 검색·본문 수집 전에 사용자 허락을 받는다 |

로컬 근거로 답이 나면 웹을 더 찾지 않는다. 현재 결정을 바꿀 중요한 사실을 로컬 근거와 모델 지식으로 확인할 수 없을 때만 웹을 제안한다. 단지 더 좋은 설계나 넓은 배경지식이 궁금하다는 이유로 검색하지 않는다. 남은 시간과 읽을 분량에 비해 판단에 주는 이득을 고려한다. 정확한 기술 동작 하나를 짧게 확인하면 해결되는 일은 모델의 기억으로 오래 추측하지 않는다. 웹을 못 쓴다는 이유로 기억을 검증된 사실처럼 쓰지 않는다.

## 웹을 쓸 때
1. 무엇을 확인할지, 웹이 필요한 이유, 찾아볼 출처·범위를 제시하고 사용자 답을 기다린다. 예: “이 버전의 지원 여부는 공식 문서 확인이 필요합니다. 해당 문서를 검색하고 본문을 읽어도 될까요?”
2. 해당 질문의 웹 조사를 이미 명시적으로 허락받았다면 같은 범위에서 다시 묻지 않는다. 단순히 ‘조사해 줘’라는 요청만으로 웹 허락을 가정하지 않는다. 범위를 넓히려면 다시 확인한다.
3. 허락한 범위에서 필요한 검색을 하고 직접 관련된 원문 부분만 읽는다. 사이트 전체 수집이나 긴 문서 전체를 문맥에 넣는 것을 기본으로 삼지 않는다. 기술은 공식 문서를 우선한다. 문서의 버전·날짜·적용 조건을 보고 주장과 실제 본문이 맞는지 대조한다. 검색 요약만 읽고 원문을 확인했다고 쓰지 않는다.
4. 결론에 URL과 확인한 내용을 연결한다. 출처끼리 다르면 차이를 밝히고, 판단에 영향을 주는 차이만 추가 확인한다. 질문에 답할 근거가 확보되면 멈춘다. 광범위한 사이트 수집은 기본 동작이 아니다.

웹 검색·텍스트 원문을 읽을 수 있는 허용 도구가 있을 때만 쓴다. 브라우저·화면 조작 도구 금지는 그대로다. 도구나 네트워크가 없으면 그 한계를 알리고, 로컬 근거·파트너 확인·사용자가 제공할 원문으로 가능한 부분을 구분한다. 개인정보·키·원문 업무 데이터를 검색어로 내보내지 않는다.

읽기 전용 역할은 메인 요청 또는 state의 현재 조사 기록에서 사용자 허락과 범위를 확인한다. 없으면 웹을 실행하지 않고 필요한 이유와 제안 범위를 답에 남긴다. 사용자에게 묻고 승인을 기록하는 것은 메인 세션이 맡는다.

## 결과에 출처를 붙인다
| 출처 | 무엇의 근거인가 | 표시 |
|---|---|---|
| 파트너 답 Q# | 이 팀의 업무 방식·판단 기준 | 답 원문과 Q# |
| README·자료·실행 결과 | 명시 제약과 관찰한 사실 | 파일:줄 또는 명령·결과 |
| 실제 읽은 기술 원문 | 해당 버전의 동작·제약 | URL과 적용 조건 |
| 일반 업무 문서·모델 지식 | 업무 가설이나 확인할 후보 | 출처와 이 팀 적용은 확인 전이라는 표시 |

기술 사실까지 파트너에게 확인받으려 하지 않는다. 도메인 후보를 구현 기준으로 쓰려면 파트너 답을 얻거나, 사용자가 가정으로 쓰기로 정한 내용을 A#로 기록한다.
