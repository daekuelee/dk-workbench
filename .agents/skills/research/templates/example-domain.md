결론: 사내 IT 헬프데스크는 보통 우선순위별 처리 기한(SLA)으로 "밀림" 을 판단하므로, 팀장의 기한 기준을 확인하는 것이 다음 질문이다.
정할 것: 확인 질문 셋을 questions.md 에 옮길지 (추천: 옮긴다, 셋 다 집계 규칙을 바꾼다)

조사 질문: 이 팀은 무엇을 기준으로 티켓이 밀렸다고 볼까. 이 답으로 집계 규칙을 정한다.

1. 현업에서 보통 어떻게 하나
- 티켓마다 우선순위가 있고, 우선순위별로 처리 기한을 둔다 (확인 전).
- 기한을 넘긴 미해결 티켓을 "기한 초과" 로 따로 본다 (확인 전).
- 아침 회의에서 담당자별 미해결 수를 확인하는 팀이 많다 (확인 전).

2. 영역 지도
```text
아는 것                 파트너 확인 필요              모름
────────────────────    ─────────────────────────    ───────────
자료 73행, 7열          밀림 기준 (기한? 상태?)        자료 갱신 주기
우선순위 칸이 있다       우선순위별 기한 차이
담당자 빈칸 9건          빈 담당자를 어떻게 보나
```

3. 용어
| 용어 | 뜻 |
|---|---|
| SLA | 처리 기한 약속. 우선순위마다 다르다 |
| 미배정 | 담당자가 아직 없는 티켓 |
| 백로그 | 쌓여 있는 미해결 티켓 전체 |
| 에스컬레이션 | 기한을 넘겨 윗선으로 올리는 것 |
| 첫 응답 시간 | 접수 뒤 첫 답까지 걸린 시간 |

4. 방식 후보와 확인 질문
| 후보 (확인 전) | 확인 질문 | 답에 따라 바뀌는 설계 |
|---|---|---|
| 생성 후 N일이 지난 미해결을 밀림으로 본다 | "보통 접수 후 며칠 지나면 밀렸다고 보던데, 팀장님은 며칠로 보세요?" | 집계 규칙의 N |
| 우선순위가 높으면 기한이 짧다 | "급한 건은 기준이 더 짧은가요?" | 규칙이 하나에서 둘로 |
| 미배정을 따로 본다 | "담당자가 없는 건은 따로 보시나요?" | 화면 맨 위 줄 |

5. 자료에서 본 사실
- 73행, 담당자 빈칸 9건, 처리일이 오늘보다 뒤인 줄 12건 (setup 실측).
