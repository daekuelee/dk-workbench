# setup fill — 고른 안으로 키트를 이번 과제에 맞춘다

입력: 사용자가 고른 안과 이유 한 줄. 이유가 없으면 한 줄을 달라고 묻고 기다린다 (이 이유가 의도 관리의 증거다).

## 고치는 파일 (이 순서로)
1. AGENTS.md "## 스택" 칸
   - 고른 안 한 줄과 사용자 이유 한 줄.
   - 실행 명령, 포트, 브라우저 경로. 서버는 0.0.0.0.
   - 설치가 필요하면 설치 명령 한 줄. 아직 실행하지 않는다.
   - 검사 명령: `./verify.sh` (서버가 떠 있어야 한다).
2. docs/plan.md
   - 목표: README 의 요청 원문을 그대로 옮긴다.
   - 요구 R#: README 에 적힌 것만 출처(README:줄)와 함께 쓴다. 파트너에게서 나올 것은 비워 둔다.
   - 하지 않는 것: 비워 둔다. 파트너에게 묻고 채운다.
   - 계단: archetypes.md 의 그 유형 계단을 이번 과제 말로 바꿔 S0~S3 을 쓴다. 완료 조건 칸은 S0 뒤에 채운다고 적는다.
   - 스택과 이유: 1과 같은 내용.
3. docs/questions.md "물을 것": docs/setup.md 의 질문 표를 순서대로 옮긴다. 왜 묻나 칸도 함께 옮긴다.
4. docs/state.md
   - 지금 단계: 질문 단계. 다음 단계: S0.
   - 실행 방법: 1의 명령.
   - 흐름: PLAYBOOK.md 구간표를 README 의 작업 시간에 맞게 비례로 줄여 옮긴다. A·C·D 유형이면 evals 역할 줄을 뺀다.
5. docs/context.md 에 "## 이번 과제" 칸을 쓴다 (explain 과 research 가 op 마다 읽는다. .agents 는 샌드박스에서 읽기 전용이라 거기에 쓰지 않는다)
   - 실제 사용자 한 줄 (모르면 "확인 전").
   - 도메인 용어 다섯 개와 한 줄 뜻. 줄마다 "(확인 전)".
   - 이번 유형에서 비유의 기준: PROFILE.md 의 강한 영역 중 이 구조와 가장 가까운 것 하나.

## 끝낸다
- docs/state.md 진행 표에 한 줄을 남긴다.
- 커밋한다. 메시지: "setup: <유형> <안> 으로 키트를 채움".
- 터미널에는 바꾼 파일 목록과 다음 할 일("파트너에게 질문 표 1번부터")만 쓰고 멈춘다.
