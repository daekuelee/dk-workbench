# setup fill — 답을 반영하고 출발할 준비가 됐는지 판단한다

## 받은 내용을 연결한다
- 병렬 read였다면 state에 연결된 이번 실행의 자료 상태·보고를 확인한다. complete일 때만 완료 보고를 근거로 읽고 다른 실행의 오래된 보고와 섞지 않는다. waiting/running이면 받은 답은 반영하되 자료는 대기 상태로 남긴다. 반복 조회로 기다리지 않는다. 자료 관찰을 파트너 답이나 사용자 선택으로 바꾸지 않는다.
- setup의 초기 이해와 questions의 기존 기록을 읽는다. 입력은 Q별 답변 칸, 자유 입력 대화, 채팅, 사용자가 지정한 로컬 파일 모두 가능하다. 여러 질문·답을 한 번에 반영할 수 있으며 답 하나마다 fill을 요구하지 않는다. AI가 제안하지 않은 질문·후속 답·사용자 수정도 포함한다. 빈 답변 칸·예문은 답으로 취급하지 않고 이미 반영한 답은 중복 등록하지 않는다.
- questions에서 사용자가 적은 질문·답·메모는 원문으로 보존하며 지우거나 요약문으로 대체하지 않는다. Q별 답변은 그 질문에 연결한다. 사용자가 질문 문구를 고쳤으면 실제 문구를 따르고 모호한 연결은 추측하지 않는다. 외부 파일은 원본 경로·위치를 연결하고 채팅으로 받은 원문은 해당 Q 또는 자유 입력 칸에 보존할 수 있다. 사용자 메모를 파트너 답으로 바꾸지 않는다. 새로운 후속 후보에는 질문 아래 빈 답변 칸도 만든다.
- AI 영역에서 Q#와 출처를 연결하고 확인된 사실·해석·미확인 및 영향을 정리한다. 원문이 길면 표 칸에 억지로 넣지 않는다. 기존 형식의 장부도 읽으며 재서식을 이유로 원문을 잃지 않는다.
- 명확한 확인·선택은 다시 묻지 않는다. 무엇을 선택했는지 모호할 때만 필요한 질문을 한다. 사용자 이유가 없으면 미기록으로 두고 AI 추천 근거와 구분한다.

## 필요한 기록에 반영한다
| 파일 | 반영할 것 |
|---|---|
| docs/questions.md | 질문의 상태·원문 위치·알게 된 사실·남은 빈 곳·R#/A# 연결. 후보는 답에 따라 갱신 |
| docs/context.md | 자료·도구 위치와 특성, 확인한 환경과 한계. 상세 관찰은 원본 기록에 연결 |
| docs/plan.md | 요청 원문·출처, 확인된 목표·범위·성공 기준, 사용자가 선택한 설계와 이유, 합의한 다음 작업 |
| docs/assumptions.md | 진행에 실제 사용하는 미확인 가정과 영향·확인 방법. 단순 미답 질문을 모두 옮기지 않음 |
| docs/setup.md | 갱신된 과제 이해와 SKILL 기준의 준비도·근거·완료 판단. 합의 원본은 plan에 연결 |
| docs/state.md | setup 완료 여부, 남은 쟁점, 다음 행동·확인 시점과 대기 |

이미 확인한 기록은 보존하고 달라진 부분만 고친다. 스택·설치·작업 단계가 아직 필요하지 않으면 미정으로 둔다. 결정했다면 plan에 구조·언어·프레임워크와 기준·선택 이유를 남긴다. README를 고치지 않고 빈칸을 채우려고 조사·설계·구현하지 않는다.

## 충분성을 판단하고 보고한다
- 먼저 “답 반영 완료”와 “setup 전체 완료 여부”를 구분해 말한다. 미완료라면 점수만 제시하지 말고 사용자의 어떤 결정이 남았는지 설명한다. 범위 선택이 남았으면 포함·제외와 추천 이유를 짧게 보이고 “이 범위로 갈까?”처럼 한 가지를 묻는다. “그 범위로 가자”라는 명확한 답이면 선택을 반영하고 완료 판단을 이어간다. 사용자가 선택 내용을 다시 긴 fill 프롬프트로 작성하게 하지 않는다.
- SKILL의 항목별 준비도를 갱신한다. 총점과 근거, 출발을 뒤집을 미확인, 사용자 확인 상태를 함께 보고한다. 응답을 받았더라도 모호하거나 상충하면 해결로 표시하지 않는다. 변경된 답은 이전 원문을 보존하며 무엇이 대체됐는지 연결한다.
- 목표 85점 이상이고 중요한 미확인이 해소·제외·명시적으로 수용됐으며 출발점이 확인됐으면 setup을 완료한다. 단순히 `fill`을 실행했다는 이유로 준비 완료를 적지 않는다. 점수를 맞추기 위해 근거를 만들거나 질문을 추가하지 않는다.
- 부족하면 반영한 내용은 저장하고 `fill 반영 완료 / setup 추가 확인 필요`로 남긴다. 큰 방향·범위·성공 기준의 남은 빈 곳을 우선해 가장 중요한 질문, 왜 지금 필요한지, 확인할 곳을 보여 준다. 세부 파일 예외는 현재 선택을 바꾸는 경우에만 앞당긴다. 확인된 질문을 다시 열거나 read부터 반복하지 않는다. 사용자에게 실제 질문 전달 또는 판단을 맡기고 멈춘다.
- 사용자가 위험을 알고 예외 종료를 선택하면 실제 점수·남은 위험·후속 확인을 보존한다. 추가 절차나 재승인을 만들지 않는다.
- setup을 완료할 때 준비 관련 변경을 로컬 커밋한다. 권한으로 막히면 문서 반영과 커밋 미완료를 구분해 보고한다. 메시지: `setup: 이번 과제의 출발 계획 반영`.
- 다음 요청은 현재 가장 필요한 확인·조사·설계·작업 후보 하나로 제안한다. 이미 맞춘 업무 흐름을 다시 확인하는 단계를 의무화하지 않는다. setup 완료 자체로 코드를 쓰거나 다음 작업을 자동 실행하지 않는다.
