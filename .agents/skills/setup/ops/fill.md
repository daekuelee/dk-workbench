# setup fill — 확인된 시작 맥락을 반영한다

## 입력을 확인한다
사용자가 docs/setup.md를 확인하거나 수정한 내용을 받는다. 준비 내용에 대한 명확한 확인이면 진행한다. 별도 비교를 요청해 추천을 받은 뒤 “추천안으로 가자”라고 했다면 그 선택도 기록한다. 무엇을 확인·선택했는지 모호할 때만 한 가지를 묻는다.

사용자의 이유가 없다고 작업을 막지 않는다. 사용자 이유는 미기록으로 두고 AI의 추천 근거와 구분한다. 이후 실제 설계 대화에서 필요할 때 보완한다.

## 필요한 기록에 반영한다
기존 내용을 보존하고 확인된 부분만 고친다. 빈칸을 채우기 위한 조사나 설계는 하지 않는다.

| 파일 | 반영할 것 |
|---|---|
| docs/context.md | 이번 과제의 자료·제공 도구 위치, 확인한 환경과 미확인. 필요한 원본 경로를 연결한다 |
| docs/plan.md | README 요청 원문·명시 제약·확인된 R#와 출처. 사용자가 이미 선택한 설계만 기록한다 |
| docs/questions.md | 첫 질문 후보와 이유. 이미 받은 파트너 답은 원문 그대로 보존한다 |
| docs/state.md | 준비 완료, 현재 미확인, 다음 대화 후보. 실행 명령이 알려졌다면 명령·포트·경로를 적는다 |

- 스택·설치·계단이 미정이면 그대로 둔다. 유형표에서 S0~S3을 복사하지 않는다.
- 스택과 선택 이유의 원본은 plan이다. AGENTS나 context에 같은 내용을 다시 쓰지 않는다.
- 도메인 용어 다섯 개나 과제별 PROMPTS 전체 복사본을 만들지 않는다. 다음 요청은 현재 기록과 PROMPTS 예문으로 구체화한다.
- 서버 실행법을 적을 때는 0.0.0.0을 사용한다. README는 고치지 않는다.

## 끝낸다
- state 진행 표에 setup.fill 완료를 남기고 준비 관련 변경을 로컬 커밋한다. 메시지: `setup: 이번 과제의 시작 맥락 반영`.
- 채팅에는 반영한 내용과 미확인을 짧게 알린다.
- 다음 프롬프트는 현재 이해를 함께 맞추는 대화로 제안한다. 예: `지금 이해한 업무 흐름과 가장 중요한 빈 곳을 먼저 보여 줘. 내가 틀린 부분을 고칠게. 조사나 구현은 아직 시작하지 마.`
- 이미 그 대화를 마쳤다면 현재 막힘에 맞게 제안한다. 다음 작업은 자동 실행하지 않는다.
