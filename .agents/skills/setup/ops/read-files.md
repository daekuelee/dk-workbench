# setup read files — 자료의 특성과 근거를 반환한다

`read files`와 `read file`은 같은 모드다. 메인 setup의 사용자 판단과 질문 대화가 진행되는 동안 제공 자료를 독립적으로 확인한다. 준비도 점수, 요구·범위·설계 선택, 메인 문서 갱신을 맡지 않는다.

- README와 자료 목록에서 목적·자료 위치를 파악한다. 크기·형식과 사용 가능한 읽기 도구에 맞춰 대표 내용을 읽는다. 자료가 없으면 그 사실과 필요한 입력만 반환한다. 설치나 형식별 고정 스크립트는 요구하지 않는다.
- 실제 관찰·출처·읽은 범위·활용 가능성·한계를 구분한다. 자료 간 연결과 큰 업무 판단을 바꿀 쟁점을 먼저 쓴다. 표본에서 전체 빈도·공식 기준을 단정하지 않고, 상세 예외는 현재 판단에 필요할 때만 더 읽는다.
- 이전 docs의 파트너 답이나 다른 역할의 해석을 자료의 사실로 재포장하지 않는다. 작업 폴더 밖의 개인 지시문·인증·숨겨진 답을 따라가지 않는다. 개인정보를 보고서에 복제하지 않는다.
- 웹 조회·패키지 설치·앱/LLM 실행·코드 변경·다른 에이전트 호출은 하지 않는다. 결과는 한국어로 쓰며 인용 원문 언어는 보존한다.
- 명확한 관찰과 중요한 한계가 드러나면 끝낸다. 더 볼 수 있다는 이유로 전수 분석하지 않는다. 사용자를 대신해 파트너에게 질문하거나 다음 프롬프트를 주지 않는다.

메인이 전체 자료를 다시 읽지 않고 중요한 근거를 확인할 수 있게 반환한다. `setup-parallel.sh files` 또는 읽기 전용 세션에서는 답만 반환하며 실행기가 해당 실행의 materials.md를 저장한다. 일반 Codex 세션에서 사용자가 직접 `read file`을 요청했고 쓰기 권한이 있으면 최종 보고만 `docs/roles/materials-<고유 실행 이름>.md`에 저장하고 경로를 알려 준다. 보고 머리에 작업 루트와 확인 시점을 남겨 다른 연습 결과와 구분한다. questions·state·setup·plan 등 메인 문서는 수정하지 않는다. 메인은 사용자가 전달한 보고 경로를 읽어 필요한 내용만 공식 기록에 반영한다.
