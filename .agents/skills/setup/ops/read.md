# setup read — 이번 과제의 시작 맥락을 준비한다

## 1. 명시된 사실을 읽는다
- SITUATION.md와 PROFILE.md에서 시험 조건과 읽는 사람을 확인한다.
- README.md를 줄 번호와 함께 읽고 파일 목록을 본다. 목표 원문·제약·마감·제공 자료·실행 지침이 있으면 출처와 함께 추린다.
- 자료는 위치와 형식을 확인한다. 형식을 모르면 필요한 일부만 열어 본다. README에 없는 업무 기준과 사용 장면은 미확인으로 둔다.
- 기존 docs/state.md와 context.md가 있으면 확인된 내용을 재사용한다. 시작 준비를 이유로 기존 요구·설계를 초기화하지 않는다.

## 2. 필요한 환경을 확인한다
준비에 영향을 주는 항목만 읽기 명령으로 확인한다. 설치나 앱 실행은 하지 않는다.
- README의 실행 언어·도구가 있으면 버전과 사용 가능 여부를 확인한다. 예: `python3 --version`, `node --version`. 언어가 미정이면 사용 가능한 언어만 적고 스택을 고르지 않는다.
- 지정된 패키지·제공된 AI 호출 도구가 있으면 위치와 사용법을 확인한다. 단지 나중에 쓸 수 있다는 이유로 패키지 후보를 모두 조사하지 않는다.
- 앱 안 AI가 필요한 과제면 제공 지침·도구를 먼저 본다. 환경 변수는 이름과 존재 여부만 확인한다. 예: `python3 -c "import os; print('\n'.join(k+'=<값 있음>' for k in os.environ if any(s in k.lower() for s in ('openai','anthropic','api_key','llm','model'))))"`. 값과 인증 파일 내용은 출력하지 않는다.
- Codex 버전은 `codex --version`으로 확인할 수 있다. 현재 모델·effort, 승인·샌드박스, 적용된 지침 경로는 세션에서 확인 가능한 정보만 적는다. 설치된 모델 목록을 추측하거나 설정 파일 전체를 덤프하지 않는다.
- 필요한 포트가 명시돼 있으면 사용 여부를 확인한다. 실행 명령·포트·경로가 아직 없으면 미정이다.
- 권한 때문에 확인하지 못한 것과 실제 미설치를 구분한다. 작업을 막는 환경 미확인은 Helper에게 물을 질문으로 남긴다. 환경 답을 기다려야 하는 항목 외에는 준비를 마친다.

## 3. 준비 보고를 쓴다
[../templates/setup.md](../templates/setup.md)를 참고해 docs/setup.md에 쓴다. 결론과 확인받을 것을 먼저 둔다.
- 목표·명시 제약·자료 위치는 파일:줄을 붙인다. 읽기 명령으로 확인한 환경에는 명령과 결과를 붙인다.
- 모르는 것은 채우지 않는다. 환경 미확인은 Helper에게, 업무 미확인은 이후 대화나 파트너에게 연결한다.
- 파트너에게 처음 보낼 작은 질문 하나와 왜 묻는지를 제시한다. question-ladder의 원칙을 따르되 전체 질문표를 만들 필요는 없다. README가 이미 답한 질문은 반복하지 않는다.
- 유형 분류, 아키텍처 선택, 열마다 이상값 세기, 도메인 용어집은 기본 보고에 넣지 않는다. 별도로 요청된 비교가 있다면 선택의 차이와 추천 근거를 추가하고 잠정임을 표시한다.

## 4. 보고하고 끝낸다
- state에 준비 보고 위치·남은 미확인·사용자 확인 대기를 기록한다.
- 채팅에는 결론, 지금 확인할 내용, 보고서 링크를 보인다. 선택을 요청했다면 선택지 차이와 추천 이유도 짧게 보인다. 네 줄에 맞추려고 판단 근거를 숨기지 않는다.
- 파트너에게 보낼 첫 질문을 코드 블록으로 준다. 실제 전달은 사람이 한다.
- 마지막에는 다음 프롬프트를 준다: `$setup fill. 준비 내용을 반영해 줘. 고칠 점은 〈없음 또는 수정할 사실〉.`
- 여기서 끝낸다. 사용자 확인 전 fill이나 과제 조사를 시작하지 않는다.
