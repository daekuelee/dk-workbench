# 문제 유형과 아키텍처 추천안

언어는 Python 을 먼저 고른다 (사용자가 읽을 수 있다). pip 설치가 막히면 표준 라이브러리 안으로 간다.

| 유형 | 알아보는 신호 | 1안 | 2안 | 검증 방식 | 흔한 함정 |
|---|---|---|---|---|---|
| A 자료를 보여 주는 웹 | 자료 파일이 있고 "한눈에", "현황", "보고 싶다" | FastAPI + HTML 한 장(fetch), 자료는 시작할 때 메모리로 읽음 | 표준 라이브러리 http.server + 서버에서 만든 HTML | S0 에서 직접 집계한 값과 API 값을 verify.sh 로 비교 | 날짜 형식, 대소문자, 중복, 빈칸, 기준일 |
| B 방식을 담은 AI 기능 서비스 | "연습", "코칭", "피드백", "돌아보기", "방식을 담고 싶다" | FastAPI + HTML 한 장 + llm.py 한 파일(호출 한 곳) + 기록은 JSON 파일 | 같은 구조, AI 대신 규칙 검사로 먼저 돌리고 AI 는 마지막 계단에 | 담당자 예시를 E# 케이스로. 구조(필드, 길이, 금지 표현)는 스크립트, 품질은 케이스마다 맞음/어긋남 | 점수 매기기, 모범 답 통째로 주기, 개인정보를 LLM 에 그대로 보냄, API 키 유무 |
| C 분석과 보고 | "왜 그런지", "원인", "정리해서 알려 달라" | Python 스크립트 + 결과를 HTML 한 장으로 | 노트북 없이 스크립트 + Markdown 보고 | 수치마다 재현 명령 | 상관을 원인으로 씀, 기준일 |
| D 업무 도구·자동화 | "매번 손으로", "반복", "변환", "보내기" | CLI 스크립트 + 얇은 웹 화면 | CLI 만 | 입력 예시 → 기대 출력 파일 비교 | 실패한 입력 처리, 되돌리기 |

## 모든 유형에 공통
- 서버는 0.0.0.0 에 바인딩하고, 포트와 경로를 README 실행 방법에 적는다.
- 첫 동작본(S1)은 30분 안에 브라우저에 뜨는 것을 목표로 한다.
- 화면은 실제 사용자의 장면(누가, 언제, 어떤 기기)에 맞춘다. 장면은 담당자에게 묻는다.
