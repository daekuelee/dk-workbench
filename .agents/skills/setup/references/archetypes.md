# 설계 후보가 필요할 때 보는 참고

과제를 이 표로 분류할 필요는 없다. 업무 흐름과 요구를 이해한 뒤 구조 후보가 막힐 때 참고한다. 후보는 출발점이며 정답·필수 계단이 아니다.

| 필요한 동작 | 가능한 구조 | 선택할 때 볼 것 |
|---|---|---|
| 자료를 화면에 보여 준다 | Python 서버 + HTML, 또는 서버에서 만든 HTML | 자료 갱신, 집계 기준, 별도 API 검증의 필요 |
| 업무 방식을 AI 기능에 담는다 | 얇은 화면 + 서버 + 외부 호출을 모은 모듈 | 제공 AI 수단, 파트너 예시, 개인정보, 기록의 사용 목적 |
| 분석 결과를 설명한다 | 분석 스크립트 + HTML 또는 Markdown | 제출 형식, 수치 재현, 상관과 원인의 구분 |
| 반복 입력을 변환한다 | CLI, 또는 업로드·결과 화면을 붙인 CLI | 실패 입력, 되돌리기, 같은 입력의 반복 처리 |

## 기술과 구현 순서를 구분한다
- 규칙으로 먼저 만들고 AI를 나중에 붙이는 것은 구현 순서 선택이다. 같은 구조를 서로 다른 아키텍처 두 개라고 부르지 않는다.
- 업무 기준이 미확인이면 안은 잠정이다. 어떤 답이 선택을 바꿀지 함께 적는다.
- Python은 사용자가 읽을 수 있다는 장점이 있다. README·기존 코드·실행 환경에 더 맞는 언어가 있으면 그 근거를 비교한다.
- 설치가 권한으로 막힌 것과 패키지를 쓸 수 없는 것은 다르다. 사용 가능 여부를 모르면 미확인으로 남긴다.
- 실행법은 state, 현재 스택과 이유는 plan에 기록한다. README를 고치지 않는다.
- 시간 배분은 PLAYBOOK을 참고한다. 이 파일에서 별도의 시간표를 만들지 않는다.
