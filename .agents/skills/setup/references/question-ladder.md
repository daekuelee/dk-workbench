# 파트너에게 묻는 법과 질문 표 쓰는 법

## 파트너는 이렇게 답한다 (SITUATION.md)
- 물은 것만, 한 번에 하나씩 푼다. 넓은 질문은 좁혀 달라고 한다.
- 해결 방법은 알려 주지 않는다. 일하는 방식, 장면, 기준, 예시는 알려 준다.
- 그래서 질문은 "무엇을 만들까요" 가 아니라 "어떻게 하고 계세요", "무엇을 보고 판단하세요" 여야 한다.

## 사다리 (사소한 것에서 깊은 것으로)
| 깊이 | 묻는 것 | 예 |
|---|---|---|
| 사소 | 사용자, 장면, 빈도, 기기 | "이건 누가 보세요?" "언제 쓰세요?" |
| 사소 | 지금 방식 | "지금은 이 일을 어떻게 하고 계세요?" |
| 중간 | 최근 장면 | "최근에 이게 문제가 된 일이 있었나요?" |
| 중간 | 판단 기준 | "무엇을 보고 ○○라고 판단하세요?" 답을 들으면 "또 보시는 게 있나요?" 로 이어 간다 |
| 중간 | 자료 믿음 | "이 자료는 어디서 오나요? 믿기 어려운 칸이 있나요?" |
| 깊음 | 예외와 경계 | "○○일 때도 같은 기준인가요?" |
| 깊음 | 완료 기준 | "어떻게 되면 됐다고 보시겠어요?" |
| 깊음 | 예시 | "잘한 예와 못한 예를 하나씩 들어 주실 수 있나요? 못한 예에는 뭐라고 하세요?" |
| 사소 | 하지 않는 것 | "이번에 안 해도 되는 건 무엇인가요?" |

## 질문 표 쓰는 법
- 지금 판단에 필요한 빈 곳부터 질문한다. 모든 빈칸을 한 번에 질문표로 만들지 않는다.
- 업무 기준을 확인하는 과정에서 빠뜨리지 않을 질문 둘: "이번에 안 해도 되는 것" 하나, "잘한 예와 못한 예" 하나. 질문표를 만들면 예시 질문은 뒤에 둔다. 첫 질문만 제안할 때 두 질문을 억지로 합치지 않는다.
- 질문표를 만들면 깊이 칸이 사소 → 중간 → 깊음 순서가 되게 정렬한다. 사소한 질문이 깊은 질문 뒤에 있으면 앞으로 옮긴다.
- "왜 묻나" 칸에는 두 가지를 쓴다: 이 답으로 알게 될 업무 사실, 답에 따라 바뀌는 설계(화면 단위, 집계 규칙, 범위).
- 도메인을 모르면 research 스킬의 후보를 "보통 ○○라고 하던데, 팀장님도 그렇게 보세요?" 꼴로 바꿔 넣는다.
- 한 질문에 한 가지만 묻는다.
- 묻지 않는 것: "할 일을 정리해 주세요", "요구사항 전부", "어떤 기능이 필요하세요", 기술 선택.
- 환경 질문(포트, 앱 안 AI API)은 Helper 에게 가는 질문으로 따로 표시한다.
