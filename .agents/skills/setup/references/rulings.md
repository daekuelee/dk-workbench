# 판정 기록 (setup)

새 판정은 맨 아래에 더한다. 날짜, 무엇이 틀렸나, 이제 어떻게 하나. 과거 기록은 보존하며 현재 행동은 SKILL과 ops를 따른다.

- 2026-10-30 · docs/setup.md 가 75줄이었다 → 60줄을 넘기지 않는다. (같은 날 사용자 판정으로 150줄로 올렸다: 길이가 아니라 맨 위 두 줄과 구조가 읽힘을 정한다.) 넘으면 자료 실측 표를 docs/reports/ 로 뺀다.
- 2026-10-30 · "정할 것" 이 맨 끝에 있어 읽는 사람이 끝까지 내려가야 했다 → 둘째 줄에 쓴다.
- 2026-10-30 · 질문에 "왜 묻나" 가 없어서 질문의 쓸모를 판단할 수 없었다 → 질문은 표로, 채울 칸과 바뀌는 설계를 쓴다.
- 2026-10-30 · 상황 시트의 "역할" 을 AGENTS.md 에서 가져왔다 → 역할은 README 에서 가져온다. 없으면 "빈칸".
- 2026-10-30 · 질문 표에 "안 해도 되는 것" 과 "잘한 예와 못한 예" 가 빠졌고, 사소한 질문(파일 확장자)이 맨 끝에 있었다 → 두 질문은 반드시 넣고, 깊이 순서로 정렬한다.
- 2026-10-30 · setup read 가 환경(언어, 설치 가능, 앱 안 AI 키, 포트)을 확인하지 않았다 → 0-b 에서 읽기만 하는 명령으로 확인하고, 키 값은 적지 않는다.
- 2026-10-30 · Codex 샌드박스(workspace-write)는 .agents, .codex, .git 을 읽기 전용으로 둔다 (codex sandbox 로 재현). Codex 가 install.sh 를 돌리자 스킬 폴더가 조용히 빠졌다. 그래서 install 은 Codex 밖 터미널에서 돌리고 끝에 스킬 파일을 확인한다. fill 의 이번 과제 칸은 docs/context.md 에 쓴다.
- 2026-10-30 · 시험장은 웹 IDE 라서 홈 폴더를 믿지 않는다. 키트는 과제 폴더 안 .kit 에 받아 설치하고 지운다. 사용자는 답 끝의 다음 프롬프트를 보고 〈 〉 만 자기 말로 채워 친다 (fill 이 docs/prompts.md 를 쓴다).

- 2026-10-30 · 준비가 유형 분류·설계·전수 실측·전체 일정까지 맡았다 → setup은 명시 사실·자료 위치·환경을 연결한다. read는 확인을 받고 fill은 확인된 맥락만 반영한다. 이유 누락으로 재승인을 요구하지 않으며 과제 풀이와 다음 op는 별도 요청으로 진행한다.

- 2026-10-30 · 시작 준비를 환경·명시 사실로만 좁혀 업무 이해와 파트너 답이 setup 밖으로 밀렸다 → read가 대표 자료의 특성·한계와 초기 업무 이해를 드러내고 질문 후보·이유를 제안한다. fill은 원문을 보존해 답을 반영하고 기본 목표 85점과 중요한 미확인·사용자 확인으로 완료를 판단한다. 질문 장부는 사용자 입력과 AI 정리를 분리한다. 전수 조사·고정 질문 순서·전면 설계는 의무화하지 않는다.

- 2026-10-30 · 질문 후보와 입력 칸이 떨어져 사용자가 질문을 다시 옮겨야 했다 → read가 Q별 질문·이유·대상을 미리 쓰고 바로 아래에 답변 칸을 둔다. 독자 질문과 여러 답의 일괄 반영도 받는다. 자료의 특정 문구가 첫 질문을 차지했다 → 업무 큰 흐름·핵심 어려움·범위·성공 판단의 빈 곳을 먼저 고르고 세부 규칙은 현재 판단에 필요할 때 확인한다. 독립 읽기를 묶고 초기 이해·질문을 문서 완료 전에 전달한다.

- 2026-10-30 · 자료·환경·보고를 모두 마칠 때까지 사용자가 기다렸다 → 선택형 read main/files로 업무 대화와 자료 확인을 분담한다. 메인은 초기 질문을 먼저 넘기고 worker 결과를 반복 조회하지 않는다. 자료 담당은 별도 보고만 반환하며 원문 입력 중인 질문 장부를 수정하지 않는다. 전체 코딩 절차를 병렬 단계로 고정하지 않는다.

- 2026-10-30 · 사용자가 선택지가 남은 다음 프롬프트를 그대로 붙여 의도가 모호해졌다 → 선택은 추천·이유와 자연어 질문 하나로 받고, 실행 요청만 복사 가능한 완성 문장으로 준다. 답 반영과 setup 완료를 구분하고 남은 사용자 판단을 명시한다. 같은 선택을 fill 문장으로 다시 작성하게 하지 않는다.
