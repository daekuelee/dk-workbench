# 시작 준비 — 행사 참가 명단 확인

현재 이해: 담당자는 참가 명단을 편하게 확인하고 싶어 한다. 접수 현장에서 사용할 것인지는 아직 모른다.
지금 할 일: 실제 사용 장면을 확인하고, 그 답에 따라 자료의 날짜가 어떤 역할을 하는지 묻는다.

## 사실과 자료 특성
- 요청 원문은 “참가 명단을 편하게 확인하고 싶어요.”이며 제한 시간은 120분이다(가상 README:3,7).
- 제공된 attendees.csv의 헤더와 서로 다른 날짜의 표본을 읽었다. 이름·참가 날짜·신청 상태가 있고 같은 이름이 다른 날짜에도 나온다(가상 자료:2–8). 이것이 중복 신청인지 서로 다른 참석 건인지는 미확인이다. 전체 중복률은 계산하지 않았다.
- 명단을 찾는 입력으로 쓸 수 있지만, 출석 기록이나 현장 본인 확인의 기준까지 제공한다고 볼 근거는 없다.
- Python 실행은 확인했고 포트는 지정되지 않았다. 스택 선택과 앱 실행은 아직 하지 않았다.

## 질문 후보 (실제 장부는 questions)
- 지금: “이 명단은 언제 어떤 일을 하면서 확인하시나요?” 사용 장면에 따라 조회와 출석 처리 중 무엇이 범위인지 달라진다. 파트너에게 묻는다.
- 사용 장면 확인 뒤: “서로 다른 날짜에 같은 이름이 있는 경우 각각 별도 참가 건인가요?” 자료를 합치거나 구분하는 기준이 달라진다. 파트너에게 묻는다.
- 사용자와 정할 것: 확인된 업무 중 제한 시간 안에 지원할 범위. 조회 방식과 기술 선택은 그 범위를 보고 결정한다.

## 준비도 (잠정)
문제·업무 10, 범위·제약 10, 성공 판단 0, 자료·환경 15, 다음 행동·미확인 15 = 50/100.
요청과 시간은 명시됐지만 사용 장면·성공 기준이 부족하다. 자료는 표본의 특성과 한계를 파악했고 다음 질문은 구체적이나 이후 범위 선택이 남았다. 사용 장면은 핵심 기능을 바꾸므로 먼저 확인한다. setup은 진행 중이다.

초기 이해가 맞는지 고치고 질문을 전달한다. 받은 답은 questions의 사용자 입력 영역이나 채팅·로컬 파일로 줄 수 있다. 원문을 모은 뒤 fill이 반영하고 다시 판단한다.
