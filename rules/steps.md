# 승인한 구현 단위를 끝내는 규칙

- 구현 전에 현재 목표·관련 R#·성공 조건을 plan 에 두고, 이번 S#의 계획을 짧게 보여 준 뒤 승인을 기다린다. 이미 승인받은 같은 계획은 다시 승인받지 않는다.
- S1 은 가장 작은 동작본이다. 다음 S#는 필요할 때 정한다. 처음부터 S0~S3을 채우지 않는다.
- S0 는 구현 전에 별도 자료 확인이 필요한 경우에만 쓴다. 판단·검증에 필요한 항목을 확인하고 기존 실측을 재사용한다. 확인된 사실은 근거 보고에, 아직 의존하는 가정은 assumptions 에 남긴다. 이미 근거가 있으면 S0 작업을 반복하지 않는다.
- 설계 대화는 실제 선택이 생길 때 한다. 사용자의 선택을 plan 에 반영한다. 미확인 업무 기준에 의존하면 잠정임을 표시한다.
- 승인된 단계 안에서 구현과 관련 검증을 마친다. 새 기능·라이브러리·범위 변경이 필요하면 영향과 선택을 먼저 보여 준다.
- 끝에는 변경·검증 결과·남은 위험을 보고한다. state와 worklog를 갱신하고 해당 단계의 변경을 커밋한다. 메시지는 "S#: 무엇". 다음 단계는 자동 시작하지 않는다.
- 화면은 사람이 미리보기 탭에서 확인한다. 관찰하지 않은 화면 결과를 통과로 기록하지 않는다. 사용자의 구조·동작·위험 설명은 worklog에 사용자 말로 남긴다.
