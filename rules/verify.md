# 검증의 근거와 범위

- 성공 조건에 필요한 검사를 고른다. 명령으로 확인할 수 있는 검사는 verify.sh에 유지하고, 변경한 기능과 기존 동작의 관련 회귀를 확인한다. 검사 개수를 늘리는 것을 완료 조건으로 삼지 않는다.
- 기대값은 앱 코드에서 가져오지 않는다. 자료를 별도로 집계한 값이나 파트너 답·예시에서 가져오고 출처를 남긴다.
- AI 출력처럼 판단이 필요한 요구는 docs/evals.md의 케이스와 기대 반응으로 본다. 구조 검사는 스크립트로, 품질은 맞음·어긋남과 근거로 기록한다.
- 검사 실패는 원인을 확인해 고친다. 해결하지 못한 것은 통과로 적지 않고 사용자에게 영향과 다음 선택을 보고한다. 환경 때문에 실행하지 못한 검사와 실제 기능 실패를 구분한다.
- localhost·외부 네트워크가 권한으로 막히면 필요한 승인을 요청하거나 사람에게 실행을 넘긴다. 서버를 안 띄운 경우도 따로 확인한다.
- 관련 검사가 하나도 없거나 실행하지 않았다면 검증 완료가 아니다. 화면은 사람의 확인 결과를 기록한다.
- 승인한 범위 밖의 기능·라이브러리는 제안만 한다. 구현에 사용하는 미확인 가정은 A#로 연결한다. 역할 의견은 사용자가 채택한 내용만 반영한다.
