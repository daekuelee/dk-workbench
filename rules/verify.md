# 범위와 검증 규칙

- plan 에 없는 기능, 라이브러리, 추상화를 더하지 않는다. 필요해 보이면 제안만 한다.
- 추정 위에 쓴 코드에는 주석 `# A#` 를 남긴다.
- 단계마다 verify.sh 에 검사를 더하고, 끝날 때 ./verify.sh 전체를 돌려 결과를 보고에 붙인다. FAIL 이 있으면 끝내지 않는다. verify.sh 는 localhost 를 부르므로 샌드박스에서 막힐 수 있다. 모든 검사가 연결 실패면 코드 탓으로 보지 말고 승인을 요청하거나 나에게 돌려 달라고 한다.
- 기대값은 앱 코드에서 가져오지 않는다. 자료를 직접 집계한 값이나 담당자 답에서 가져온다.
- docs/evals.md 에 E# 가 있으면, 그 기능을 바꾼 단계 끝에 케이스를 앱에 넣어 보고 결과 칸을 채운다.
- docs/roles/ 의 답은 내가 채택한 줄만 plan, assumptions, evals 로 옮긴다.
